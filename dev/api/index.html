API reference

QwenDecisionCore.QwenDecisionCore — Module
QwenDecisionCore

Shared, dependency-light core for native-Julia decision models built on Qwen3.5 / Qwen3.8 hybrid backbones. It owns the backbone forward pass (partial RoPE, full attention, Gated DeltaNet, RMS normalization, MLP), the safetensors loader, Hugging Face checkpoint resolution, the CPU policy, the accelerator extensions, and the ordered Choice / Noul / Score question types with their TypeSafe confidence formulas. Decision heads (a linear readout, a pointer head, ...), tokenization, and checkpoint-format specifics belong to client packages such as KevClient.

QwenDecisionCore.ChoiceQuestion — Type
ChoiceQuestion(criteria; instructions="")

Construct a choice question from an ordered vector of string key => description pairs. The order must match the option columns in the model's logits.

QwenDecisionCore.NoulQuestion — Type
NoulQuestion(; instructions="")

Construct a yes/no question. Model columns must be ordered false, true.

QwenDecisionCore.QwenBackbone — Type
QwenBackbone(directory; device=:cpu)

Load a text-only Qwen3.5 / Qwen3.8 backbone directly from safetensors. The complete forward pass is implemented in Julia; the decision head (linear readout, pointer head, ...) is owned by the client package, not here. Inputs are prepared token IDs and masks; tokenization is not part of this API. Only float32 inference, default partial RoPE, and bias-free projections are currently supported.

directory is a local checkpoint directory or a Hugging Face repository ID. Use device=:metal after importing Metal for Apple GPU execution, device=:cuda after importing CUDA for NVIDIA GPU execution, or device=:amdgpu after importing AMDGPU for AMD GPU execution. CPU inference automatically selects its platform policy.

QwenDecisionCore.ScoreQuestion — Type
ScoreQuestion(criteria; instructions="")

Construct a question with 2 to 10 ordered scale descriptions. Returned scores use the client's zero-based scale, from 0 to length(criteria) - 1.

QwenDecisionCore.backbone_hidden — Function
backbone_hidden(backbone, input_ids, attention_mask[, positions])

Run the backbone over one sequence and return final-normalized hidden states with shape (hidden, length(positions)) (every position when positions is omitted). input_ids and attention_mask are vectors, or a single-row matrix. Multiple sequences are processed one at a time; batching and a KV cache are not implemented here.

QwenDecisionCore.backbone_last_hidden — Method
backbone_last_hidden(backbone, input_ids, attention_mask)

Final-normalized hidden state of the last position only, as a vector of length hidden. A linear readout needs nothing else, so this uses the last-token forward (native_hidden_forward), which accelerator and CPU paths specialize; it is cheaper than backbone_hidden(...)[:, end].

QwenDecisionCore.resolve_checkpoint — Method
resolve_checkpoint(model_id_or_path; revision="main", cache_dir=nothing,
                   offline=hub_offline(), required=DEFAULT_REQUIRED,
                   auxiliary=DEFAULT_AUXILIARY, patterns=DEFAULT_PATTERNS)

Return a complete local checkpoint directory. Look up repository IDs in the existing Hugging Face cache, then in this package's Scratch cache; download only missing files if needed. A local directory is validated and returned without downloading.

Pass an immutable 40-character commit as revision for reproducibility. Branch names resolve to immutable snapshots on first download; subsequent calls reuse the cached reference. cache_dir overrides Scratch storage for this call. HF_HUB_CACHE, HF_HOME, HF_ENDPOINT, HF_TOKEN, and HF_HUB_OFFLINE are respected. Partial downloads are kept outside completed snapshot files and are removed on failure.

required lists files that must be present, auxiliary optional files that are still downloaded, and patterns regexes for weight shards (a client checkpoint can add its adapter and head files).

QwenDecisionCore.write_native_weights — Method
write_native_weights(path, tensors; metadata=nothing)

Write tensors (a name => array map) as safetensors. Arrays are stored the same way read_native_weights reads them, so a round trip is exact; a PyTorch Linear weight written from Julia's (in, out) layout is stored with the reversed shape and read back by torch as (out, in).
